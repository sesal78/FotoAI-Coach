<task type="auto">
  <name>Task 2: Parallelise dashboard fetches with Promise.all</name>
  <files>nextjs_space/app/dashboard/page.tsx</files>
  <action>
  Refactor `loadDashboardData()` (currently lines 90-178) to fire all 4 fetch calls in parallel using Promise.allSettled:

  Current pattern (sequential):
  ```
  const challengesRes = await fetch(challenges_url, ...);
  // process challenges...
  const progressRes = await fetch(progress_url, ...);
  // process progress...
  const recentRes = await fetch(recent_url, ...);
  // process recent...
  const itineraryRes = await fetch(itinerary_url, ...);
  // process itineraries...
  ```

  Target pattern (parallel):
  ```
  const [challengesResult, progressResult, recentResult, itineraryResult] = await Promise.allSettled([
    fetch(`/api/challenges?userId=${userId}&status=pending&limit=1`, { cache: 'no-store' }),
    fetch(`/api/progress?userId=${userId}`, { cache: 'no-store' }),
    fetch(`/api/challenges?userId=${userId}&status=all&limit=5`, { cache: 'no-store' }),
    fetch(`/api/itinerary?userId=${userId}`, { cache: 'no-store' }),
  ]);
  ```

  Use Promise.allSettled (NOT Promise.all) so one failing endpoint does not block others. Process each result individually with its existing error handling and state updates. Keep the localStorage fallback logic for challenges intact.

  Preserve all existing console.log statements, toast calls, and error handling. Only change the fetch orchestration — do not alter the response processing logic.

  Do NOT introduce React Query hooks yet (that is plan 02-02). This is purely a fetch orchestration improvement.
  </action>
  <verify>cd nextjs_space && npx tsc --noEmit — no type errors; yarn lint — no new lint warnings</verify>
  <done>loadDashboardData() fires all 4 fetches simultaneously via Promise.allSettled, each result processed independently with existing error handling preserved, localStorage fallback intact</done>
</task>
