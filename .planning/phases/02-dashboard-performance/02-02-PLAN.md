<objective>
Replace manual fetch + useState in the dashboard with React Query hooks for caching, background refetch, and deduplication.

Purpose: The dashboard currently manages loading/error/data state manually with useState and raw fetch calls. React Query provides automatic caching (5-min stale time from provider defaults), background refetch on window focus, request deduplication, and cleaner component code. This eliminates redundant API calls when navigating back to the dashboard and improves perceived performance.
Output: Custom React Query hooks for dashboard data, dashboard page refactored to use them.
</objective>

<task type="auto">
  <name>Task 1: Create React Query hooks for dashboard data</name>
  <files>nextjs_space/hooks/use-dashboard-data.ts</files>
  <action>
  Create `nextjs_space/hooks/use-dashboard-data.ts` with 'use client' directive. This file exports 4 custom hooks:

  1. `usePendingChallenge(userId: string | undefined)` — wraps `useQuery`:
     - queryKey: `['challenges', 'pending', userId]`
     - queryFn: fetches `/api/challenges?userId=${userId}&status=pending&limit=1`, returns `Challenge | null`
     - enabled: `!!userId`
     - Parse response, extract `challenges[0]` or null
     - On success: store in localStorage as `currentChallenge` (preserve existing offline fallback)
     - placeholderData: read from localStorage `currentChallenge` on mount (parsed, or undefined)

  2. `useUserProgress(userId: string | undefined)` — wraps `useQuery`:
     - queryKey: `['progress', userId]`
     - queryFn: fetches `/api/progress?userId=${userId}`, returns `UserProgress | null`
     - enabled: `!!userId`

  3. `useRecentChallenges(userId: string | undefined)` — wraps `useQuery`:
     - queryKey: `['challenges', 'recent', userId]`
     - queryFn: fetches `/api/challenges?userId=${userId}&status=all&limit=5`, returns `Challenge[]`
     - enabled: `!!userId`

  4. `useItineraries(userId: string | undefined)` — wraps `useQuery`:
     - queryKey: `['itineraries', userId]`
     - queryFn: fetches `/api/itinerary?userId=${userId}`, returns itinerary array
     - enabled: `!!userId`

  Also export a helper `useInvalidateDashboard()` that returns a callback using `useQueryClient().invalidateQueries()` to invalidate all dashboard-related query keys. This will be called after mutations (generate challenge, submit, skip, etc.).

  Import the Challenge and UserProgress interfaces from the dashboard page — or better, move those interfaces to `nextjs_space/lib/types.ts` if they don't already exist there. Check `lib/types.ts` first.

  All fetch calls use `cache: 'no-store'` to match current behavior. Do NOT add React Query staleTime overrides — use provider defaults (5 min from plan 02-01).
  </action>
  <verify>cd nextjs_space && npx tsc --noEmit — no type errors</verify>
  <done>4 React Query hooks + invalidation helper exported, TypeScript compiles cleanly</done>
</task>
