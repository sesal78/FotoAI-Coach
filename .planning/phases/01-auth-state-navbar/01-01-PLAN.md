<objective>
Centralize auth state into a React AuthContext so all components share a single /api/auth/me fetch instead of each calling it independently.

Purpose: Currently both Navbar and DashboardPage each mount their own useAppwriteAuth() hook, causing 2 separate /api/auth/me HTTP calls on every authenticated page load. A shared AuthContext means one call at app root, zero duplication, and no navbar flicker.

Output:
- New file: nextjs_space/contexts/auth-context.tsx (AuthProvider + useAuth hook)
- Updated: nextjs_space/app/layout.tsx (wraps app with AuthProvider)
- Updated: nextjs_space/hooks/useAppwriteAuth.ts (thin proxy → useAuth)
</objective>

**Current problem:**
- `useAppwriteAuth()` fetches `/api/auth/me` on every mount
- `Navbar` (components/navbar.tsx:32) calls `useAppwriteAuth()` → 1 fetch
- `DashboardPage` (app/dashboard/page.tsx:55) calls `useAppwriteAuth()` → 1 fetch
- Result: 2 `/api/auth/me` requests per page load, independent loading states → navbar flicker

**Target pattern:**
- `AuthProvider` in layout.tsx holds ONE instance of the fetch + state
- `useAppwriteAuth()` becomes a thin proxy calling `useContext(AuthContext)` — no fetch, zero breaking changes for consumers
- All components that import useAppwriteAuth automatically get context-backed state

**Appwrite session cookie:** `foto_session`

**AppwriteUser type (existing, keep as-is):**
```ts
export interface AppwriteUser {
  id: string;
  email: string;
  name: string;
}
export type AuthStatus = 'loading' | 'authenticated' | 'unauthenticated';
```

**layout.tsx constraint:** It's a Server Component (no 'use client'). AuthProvider must be a Client Component rendered inside the Server layout — this is the standard Next.js 14 pattern. The provider file needs 'use client'.
</context>
