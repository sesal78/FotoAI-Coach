<objective>
Add server-side file validation before Appwrite upload and decouple LLM feedback generation from the submission HTTP request.

Purpose: Currently the photo upload has no server-side validation (Appwrite enforces at storage level but errors are caught silently), and the `generateFeedback()` LLM call blocks the entire submission response for 2-5 seconds. Validating early gives clear user-facing errors. Decoupling feedback lets the submission response return immediately.
Output: Validated upload with clear error messages, submission saved immediately with `feedbackStatus: 'pending'`, feedback generated asynchronously via fire-and-forget.
</objective>

  **Step 2: Refactor POST /api/submissions to save immediately, feedback async**

  In the POST handler of `nextjs_space/app/api/submissions/route.ts`:

  a) REMOVE the synchronous `generateFeedback()` call (lines 143-154). Do NOT await feedback before creating the submission.

  b) Create the submission document WITH `feedbackStatus: 'pending'` and `feedback: null`:
     ```
     const submissionDoc = await databases.createDocument(
       DATABASE_ID,
       COLLECTION_CHALLENGE_SUBMISSIONS,
       ID.unique(),
       {
         challengeId,
         userId,
         photoUrl,
         notes,
         feedback: null,
         feedbackStatus: 'pending',
         rating: rating ? parseInt(rating) : null,
         submittedAt: new Date().toISOString(),
       }
     );
     ```

  c) After the submission document is created (and challenge status updated, progress updated, agent action logged), return the response immediately — do NOT wait for feedback.

  d) AFTER the response object is constructed but BEFORE returning it, fire-and-forget the feedback generation. Use a self-executing async function that does NOT block the response:

     ```
     // Fire-and-forget: generate feedback asynchronously
     // Safe in Docker standalone mode — Node.js keeps event loop alive
     generateFeedbackAsync(databases, submissionDoc.$id, {
       challengeText: challenge.challengeText as string,
       userNotes: notes || undefined,
       skillLevel: preferences?.skillLevel || 'intermediate',
     }).catch((err) => {
       console.error('Async feedback generation failed:', err);
     });
     ```

  e) Create a helper function `generateFeedbackAsync` at the bottom of the file (before `getProgressFieldForChallengeType`):

     ```
     async function generateFeedbackAsync(
       databases: any,
       submissionId: string,
       context: { challengeText: string; userNotes?: string; skillLevel: string }
     ) {
       try {
         const feedback = await generateFeedback(context);
         await databases.updateDocument(
           DATABASE_ID,
           COLLECTION_CHALLENGE_SUBMISSIONS,
           submissionId,
           {
             feedback,
             feedbackStatus: 'ready',
           }
         );
         console.log('✅ Async feedback generated for submission:', submissionId);
       } catch (error) {
         console.error('❌ Async feedback failed for submission:', submissionId, error);
         // Update status to indicate failure — user can still see submission without feedback
         try {
           await databases.updateDocument(
             DATABASE_ID,
             COLLECTION_CHALLENGE_SUBMISSIONS,
             submissionId,
             {
               feedback: 'Great work completing this challenge! Keep practicing and exploring your creative vision.',
               feedbackStatus: 'ready',
             }
           );
         } catch (updateError) {
           console.error('❌ Failed to update fallback feedback:', updateError);
         }
       }
     }
     ```

  f) Update the response to NOT include feedback (it's not available yet):
     ```
     return NextResponse.json({
       submission: { ...submissionDoc, id: submissionDoc.$id },
       message: 'Challenge submitted successfully! Feedback is being generated...',
     });
     ```

  **Important:** The `generateFeedbackAsync` call must happen AFTER the response return statement logic is set up but must be invoked BEFORE the return. Since JavaScript is single-threaded, calling the async function (without await) starts the promise but doesn't block. The function returns its result after the HTTP response is sent. This is safe because the Docker standalone Node.js process keeps the event loop alive.

  **What NOT to do:**
  - Do NOT use `waitUntil` (not available in standalone mode)
  - Do NOT create a separate endpoint for triggering feedback (that's over-engineering)
  - Do NOT change the `generateFeedback` function in `lib/llm.ts`
